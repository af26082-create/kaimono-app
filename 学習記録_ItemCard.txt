ItemCard コンポーネント制作の記録

======================================================================
1. 自分から質問したポイント
======================================================================

Q1. Category型は「購入するものの種類」という意味？
    → その通り。ただし name（品名）とは役割が違う。
      name     : 「牛乳」「洗剤」など、何を買ったかを個別に書く。自由入力
      category : 「食費」「日用品」など、どの分類かをまとめる。選択式
      分けている理由は集計のため。品名だけでは「今月は食費に3,500円」
      という集計ができない。

Q2. props関連の書き方が分からない
    → propsは親から子へ値を渡す仕組み。HTMLの属性に似ている。
      ・型を先に決める（type ItemCardProps = { ... }）
      ・関数の引数で受け取る（分割代入 { item, onToggle } が一般的）
      ・関数もpropsとして渡せる。型は (id: string) => void
      ・onClick には「実行結果」ではなく「関数そのもの」を渡す。
        引数がある場合は () => 関数(引数) と包む

Q3. 仮データはどう置けばいい？
    → const item1: Item = { ... } の形。型注釈 : Item を必ず付ける。
      コンポーネントの外に置く（中に書くと再描画のたびに作り直される）。
      複数並べるときは、まず変数を2つ作る方法で動かし、
      動いてから配列 + .map() に変える。

Q4. エラーの原因が理解できない（26個出た）
    → 構文エラーは連鎖する。1か所で文の区切りを見失うと、
      それ以降が全部おかしく見える。
      必ず一番上のエラーから直す。1つ直すと10個消えることがある。

Q5. 削除ボタンが右端に寄らない
    → display: flex は「親としての指定」（子を横に並べる）。
      flex: 1 は「子としての指定」（親から余った幅をもらう）。
      向きが逆なので、同じ要素に両方書いても押し出しは起きない。
      文字情報をまとめる内側の箱を作り、そちらに flex: 1 を付ける。

2. 自分がミスしていたところ
======================================================================

--- types.ts ---

(1) CATEGORIES を「型」として定義していた
    型はビルドすると消えるので、実行時に .map() で選択肢を並べられない。
    値としての配列 + as const が必要。

(2) Category をオブジェクト型にしていた
    { 食費: string, ... } は「全項目を持つオブジェクト」の意味になり、
    item.category に '食食' を入れられない。
    正しくは (typeof CATEGORIES)[number] で配列から型を作る。

(3) ItemStatus を作ったのに Item の中で使っていなかった

(4) itemTotal に export が無く、let で宣言していた（const が適切）

(5) 値である CATEGORIES を export type で書き出そうとした
    出口は2つ必要： export {値}  /  export type {型}

(6) 型の export 行ごと削除してしまい、Item が外から使えなくなった

--- ItemCard.tsx ---

(7) JSX を関数の外に書いていた（JSXは return の中にしか書けない）

(8) 型 ItemCardProps を値として使おうとした
    型は設計図、props が実物。使うのは props のほう。

(9) JSX の中で {} を使わず、文字列がそのまま表示される状態だった

(10) export default が無く、App.tsx から読み込めなかった

(11) return の中に要素が3つ並んでいた
     → JSX expressions must have one parent element
     <div> か <> </> で包む必要がある

(12) 購入日として createdAt を「製造日」と表示していた
     createdAt は「データを登録した日時」。表示すべきは boughtAt。
     さらに、購入済みのときだけ出す条件が抜けていた。

(13) メモが空でも「食費・」と中黒だけが残っていた

(14) チェックボックスと「買った」ボタンが同じ動作で重複していた
     同じ操作の入口が2つあると、使う人が迷い、変更時にズレる。

(15) フォルダ名 conponents（正しくは components）、
     ファイル名 type.ts（方針では types.ts）

--- App.tsx ---

(16) import './components/ItemCard' と書いた
     これは「ファイルを実行するだけ」の書き方。
     default export を受け取るには import ItemCard from '...' が必要。

(17) props名を Item と大文字で書いた（受け取る側は item。大小は別物）

(18) JSX の中に型注釈を書いた（item={item1:Item}）
     型注釈は変数を作るときだけ。渡すときは値だけ。

(19) アロー関数の引数に (item.id) と書いた
     丸括弧の中は「これから受け取る値に付ける新しい名前」を書く場所。

(20) console.log({item.id}) と余計な {} を書いた
     JSX の中の {} は「JavaScriptへの切り替え」、
     JavaScript の中の {} は「オブジェクトを作る記号」。意味が違う。

(21) <div className="app"> を <h1> に変えてしまい、h1 の中に h1 が入った
     型チェックはタグの意味までは見ない。
     「型チェックが通る＝正しい」ではない。

(22) 保存し忘れたまま「直った」と判断した（自動保存を有効にして解決）

--- CSS ---

(23) 箱が1つしかなく、6つの要素が全部横一列に並んでいた

(24) flex: 1 を、その要素自身（親）に付けていた

3. 今回使った React の重要な要素
======================================================================

【コンポーネント】
・コンポーネントは「JSXを返す関数」。名前は大文字始まりにする。
  React は大文字始まりを自作コンポーネント、小文字始まりを
  HTMLタグとして区別している。

【JSX】
・return が返せるのは1つの要素だけ。複数並べるときは
  <div> か <> </>（フラグメント）で包む。
・{} は「ここからJavaScript」への切り替えスイッチ。
  {item.name} のように囲まないと、文字がそのまま表示される。

【props】
・親から子へ値を渡す仕組み。型を先に決めておく。
    type ItemCardProps = {
      item: Item
      onToggle: (id: string) => void
    }
・受け取り方は props.item でも、分割代入 { item } でもよい。
・関数もpropsとして渡せる（コールバック）。
  onClick={() => onToggle(item.id)} の () => は「包み紙」。
  外すと画面表示の瞬間に実行されてしまう。

【条件付きレンダリング】
・「出す / 出さない」    → {条件 && <p>...</p>}
・「AかB、必ずどちらか」 → {条件 ? <A /> : <B />}
・注意：&& の左に数値を書くと、0 のとき画面に「0」と表示される。

【制御されたコンポーネント】
・checked と onChange は必ずセットで書く。
  「見た目はデータが決める、操作はデータを変える」という一方通行にすると、
  画面とデータがずれなくなる。

【プレゼンテーショナルコンポーネント】
・ItemCard は表示に専念し、自分でデータを書き換えない。
  「押されたよ」と親に伝えるだけ。
  こうすると、買い物リストでは「購入済みにする」、
  支出一覧では「予定に戻す」と、同じ見た目のまま動作を差し替えられる。

【import / export】
・default export  → import ItemCard from './ItemCard'（{} なし）
・名前付き export → import { itemTotal } from '../types'（{} あり）
・型だけ          → import type { Item } from '../types'
・CSS             → import './ItemCard.css'（名前を付けない）

【TypeScript】
・ユニオン型： 'planned' | 'bought'  … どれか1つ
・as const   ： 配列の中身を型として固定する
・(typeof CATEGORIES)[number] ： 配列から型を自動生成する
・型は実行時に消える。値と型は別物として扱う。

【CSS / Flexbox】
・display: flex  … 親としての指定（子を横に並べる）
・align-items    … 縦方向の位置揃え
・gap            … 子要素の間隔
・flex: 1        … 子としての指定（親の余った幅をもらう）
・margin-left: auto … flexの中で1つだけ右端に寄せる定番テクニック

【使ったツール】
・npx tsc -b        … 型チェックを手動で実行する
・F12 → Console     … console.log の出力を確認する
・Shift + Alt + F   … VS Code のコード自動整形

4. ふりかえりの質問への回答
======================================================================

--- Q1. AIには何をお願いした？ ---

コードを書いてもらうのではなく、次の4つをお願いした。

・実装方針の説明
  何を作るか、どのファイルに、どんな props を受け取る形にするか。
  この段階ではコードを書かないよう依頼した。
・分からない文法の解説
  props の書き方、オブジェクトの作り方、条件によって表示を変える方法。
  自分のコードの答えではなく、別の例で説明してもらった。
・自分が書いたコードのレビュー
  良いところと、間違っているところを理由つきで指摘してもらった。
・エラーメッセージの読み解き
  何を言っているのか、どこから直せばよいのかを教えてもらった。

途中で「方針の説明 → 自分で書く → レビュー → 書き直し」という手順を
ルールとして決めた。ItemCard のコードは自分で書いた。

--- Q2. どのファイルを変更した？ ---

［新しく作った］
 src/types.ts                  データの形（Item型など）と合計計算の関数
 src/components/ItemCard.tsx   項目1件分を表示する部品
 src/components/ItemCard.css   ItemCard の見た目

［書き換えた］
 src/App.tsx        仮データ2件を用意し、ItemCard を2つ表示するようにした
 vite.config.ts     ポートの固定と、ファイル監視方式の変更（環境対応）

［記録として作った］
 設計書.txt          アプリの設計
 CLAUDE.md           技術構成と進め方のルール

--- Q3. この部分は何をしている？ ---

［types.ts］
 CATEGORIES   カテゴリの選択肢。配列（値）なので画面にも並べられる
 Category     その6つのどれか、を表す型。打ち間違いを防ぐ
 Item         項目1件の形。9つの情報を持つ
 itemTotal()  単価 × 個数 を計算する。合計は保存せず毎回計算する

［ItemCard.tsx］
 ItemCardProps               受け取る値の取り決め（item と関数2つ）
 checked={item.status === 'bought'}
     文字列を === で比較して true / false に変換し、チェック状態にする
 onChange={() => onToggle(item.id)}
     押されたら、親に id を伝える。自分ではデータを変えない
 {item.memo !== "" && ` ・ ${item.memo}`}
     メモがあるときだけ、中黒ごと表示する
 {item.boughtAt !== null && <p>購入日: ...</p>}
     購入日があるときだけ、その行を出す
 itemTotal(item).toLocaleString()
     合計を計算し、3桁区切りにする

［ItemCard.css］
 .item-card       display: flex でチェック・本文・ボタンを横に並べる
 .item-card__body flex: 1 で余った幅をもらい、削除ボタンを右端へ押し出す

［App.tsx］
 item1 / item2    動作確認用の仮データ。1件は予定、1件は購入済み
 console.log      ボタンが押されたことを確認するための仮の処理

--- Q4. なぜこの実装になった？ ---

・買い物予定と支出を1種類の Item で表した
  status で区別すれば、チェックは「status を変える」だけで済む。
  2種類のデータに分けると、片方だけ消えるといった同期のバグが起きる。
  同じ部品を買い物リストと支出の両方で使い回せる利点もある。

・合計金額を保存せず、計算で出すことにした
  合計を保存すると、個数を変えたときに直し忘れて数字が食い違う。
  元になる値だけを持つほうが安全。

・カテゴリを「配列 + そこから作った型」の2つで持った
  型は実行時に消えるので、画面の選択肢を作るには値の配列が必要。
  型があると打ち間違いをその場で見つけられる。
  as const を使うと、リストを2回書かずに済む。

・ItemCard は表示に専念し、データを書き換えない形にした
  買い物リストでは「購入済みにする」、支出一覧では「予定に戻す」と、
  同じ見た目のまま動作だけ差し替えられるようにするため。

・checked と onChange を必ずセットで書いた
  見た目はデータが決め、操作はデータを変える、という一方通行にすると
  画面とデータがずれない（制御されたコンポーネント）。

・日付を Date 型ではなく文字列で持った
  localStorage に保存すると、どのみち文字列になるため。

・CSS を2階層の構造にした
  横並び（チェック・本文・ボタン）と縦積み（本文の3行）を
  同時に成り立たせるには、箱が2つ必要だった。

--- Q5. この変更で何が変わった？ ---

［前］
 見出し「買い物・支出管理アプリ」だけが表示される画面。

［後］
 ・仮データ2件がカードとして表示される
 ・購入済みの項目はチェックが入った状態で表示される
 ・購入済みの項目にだけ購入日が表示される
 ・メモが空の項目には、中黒が出ない
 ・削除ボタンがカードの右端に配置される
 ・ボタンを押すと、対象の id が Console に出力される

部品としては完成した状態。あとはデータの保管場所（Context）につなげば、
チェックや削除が実際にデータを書き換えるようになる。

また types.ts ができたことで、これから作る他のコンポーネントも
同じデータの形を前提に書けるようになった。

--- Q6. 動かなかったときは何が原因だった？ ---

［環境の問題］
 ・localhost を開いたら別のアプリが表示された
   → 別プロジェクトの開発サーバーが 5173 番を使っていて、
     こちらは 5174 番にずれていた。ポートを固定して解決。
 ・保存しても画面に反映されない
   → Vite が OS からのファイル変更通知を受け取れていなかった。
     usePolling（自分から定期的に見に行く方式）に切り替えて解決。
 ・直したはずなのに変わらない
   → ファイルを保存していなかった。自動保存を有効にして解決。

［コードの問題］
 ・エラーが26個出た
   → 原因は5つだけ。構文エラーが連鎖して増えていた。
     (1) JSX の中に型注釈を書いた
     (2) props 名の大文字・小文字が合っていなかった
     (3) アロー関数の引数に item.id と書いた
     (4) console.log に余計な {} を付けた
     (5) import の書き方が違った（default export の受け取り方）
 ・JSX expressions must have one parent element
   → return の中に要素が複数並んでいた。div で包んで解決（2回発生）
 ・Module declares 'Item' locally, but it is not exported
   → export type の行ごと削除してしまい、型が外に出せなくなっていた
 ・削除ボタンが右端に寄らない
   → 内側の箱がなく、flex: 1 を親自身に付けていた。
     display: flex は親としての指定、flex: 1 は子としての指定。

［学んだこと］
 エラーは敵ではなく、どこが違うかを教えてくれるヒント。
 一番上のエラーから直すと、まとめて消えることが多い。
 型チェックが通っても正しいとは限らない（h1 の中に h1 を入れてしまった例）。
