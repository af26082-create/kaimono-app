買い物・支出管理アプリ 設計書

======================================================================
① 作るアプリ
======================================================================

【何をするアプリなのか】

買い物の予定と支出を、1つのアプリでまとめて管理するWebアプリです。
買いたいものを事前に登録しておき、実際に買ったらチェックを入れると、
その内容が自動的に支出として記録されます。
買い物リストを経由せず、支出だけを直接登録することもできます。

【誰が・どんなときに使うのか】

一人暮らしを始めたばかりで、買い物にまだ慣れていない学生を想定しています。
  
・買い物に行く前に、買うものと予定金額を登録する
・店でリストを見ながら買い物し、買ったものにチェックを入れる
・あとから「今月は何にいくら使ったか」を振り返る

【なぜ作るのか】

買い物メモアプリと家計簿アプリを別々に使うと、同じ商品を2回入力する
ことになり、面倒で続きません。「チェックを入れる」という1回の操作で、
買い物メモと家計簿の両方を済ませられるようにするのが狙いです。


======================================================================
② 実装する機能
======================================================================

【絶対に作りたい機能】

1. 買い物リストへの登録（品名・単価・個数・カテゴリ・メモ）
2. 買い物リストの一覧表示
3. チェックを入れると購入済みになり、自動で支出として記録される
   （購入日は自動で付与）
4. 支出一覧の表示と、合計金額の計算
5. 買い物リストを経由しない、支出の直接登録
6. 登録した項目の編集・削除
7. localStorageへの保存（ブラウザを閉じてもデータが残る）

【時間があれば追加したい機能】

・カテゴリ別の集計とグラフ表示
・月ごとの絞り込みと、その月の合計金額
・予算の設定と、残額・使いすぎの警告
・買い物リストの検索・並び替え
・「よく買うもの」からのワンタップ登録
・購入の取り消し（支出から買い物リストに戻す）


======================================================================
③ 必要な画面
======================================================================

画面は1つだけです。1ページの中を上下2つのセクションに分け、
スクロールで行き来する構成にします。

【画面全体の構成（上から順に）】

1. ヘッダー
   アプリ名を表示する

2. 買い物リストセクション
   ・これから買う予定のものを一覧表示する
   ・新しい項目を追加するフォーム
   ・チェックを入れて購入済みにする
     → その項目が下の支出セクションへ移動する
   ・項目の編集・削除

3. 支出セクション
   ・購入済みの項目を、購入日の新しい順に一覧表示する
   ・合計金額を表示する
   ・買い物リストを経由せず、支出を直接登録するフォーム
   ・項目の編集・削除

【この構成にした理由】

チェックを入れた項目が上のリストから消えて下の支出一覧に現れる、
という動きがその場で目に見えます。
「買い物メモと家計簿が1つの操作でつながる」というこのアプリの
一番の特徴が、画面を移動しなくても伝わります。


======================================================================
④ コンポーネント
======================================================================

Header
  アプリ名を表示する

ItemForm
  項目の入力フォーム。
  買い物リストへの追加と支出の直接登録の両方で使い回す

ItemList
  項目を並べて表示する。0件のときの案内文も担当

ItemCard
  項目1件分の表示。品名・金額・カテゴリ・状態と、
  チェックボックス・削除ボタン

TotalBar
  合計金額の表示

Button
  ボタンの見た目を統一するための共通部品

ItemsProvider
  画面部品ではなく、データをアプリ全体に配るための部品（Context）

買い物リストと支出は、status（予定／購入済み）が違うだけの同じデータ
として扱う設計にしたため、ItemForm と ItemList は買い物リストセクション
と支出セクションの両方で共通して使えます。
同じ部品を2か所で使い回せることが、この設計の利点です。


======================================================================
⑤ 技術構成
======================================================================

【言語・フレームワーク】

・React 19 + TypeScript
・ビルドツール: Vite
・Next.jsは使用しない

【スタイリング】

・通常のCSS（Tailwind CSSなどのCSSフレームワークは使用しない）

【使用するライブラリ】

・外部ライブラリは使用しない
　画面を1つにまとめたため、ルーティング用の react-router-dom は
　不要と判断した
・状態管理ライブラリ（Reduxなど）は使用せず、
　Reactの useState / useContext の範囲で実装する

【API】

・外部APIは使用しない

【データの保存】

・ブラウザの localStorage に保存する
・保存キー: kaimono-app.items
・項目の配列を JSON.stringify で文字列に変換して保存し、
　起動時に JSON.parse で復元する
・useEffect でデータの変更を検知し、自動で保存する
・外部データベースや認証機能は今回は扱わない

【データ構造】

type Item = {
  id: string          // 重複しないID
  name: string        // 品名
  unitPrice: number   // 単価
  quantity: number    // 個数
  category: Category  // 食費 / 日用品 / 衣類 / 趣味・娯楽 / 交通 / その他
  memo: string        // メモ
  status: 'planned' | 'bought'  // 買う予定 / 購入済み
  boughtAt: string | null       // 購入日（未購入ならnull）
  createdAt: string             // 登録日時
}

合計金額は保存せず、単価 × 個数 でその都度計算します。
保存する値を最小限にして、データの食い違いが起きないようにするためです。
